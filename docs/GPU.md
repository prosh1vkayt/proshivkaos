# GPU на mido: Adreno 506 и freedreno

Коротко: **GPU — самый длинный путь к скорости, и не единственный.**
Всё, что ниже, — разбор, чтобы работа над GPU шла по шагам с проверяемым
результатом, а не «портировать Mesa и посмотреть».

## Что за железо

Из дерева устройств телефона и мейнлайн-драйвера `drivers/gpu/drm/msm`:

| | |
|---|---|
| GPU | Adreno 506, chip id `0x05000600`, семейство A5xx |
| Регистры | `0x01C00000`, 256 КБ; прерывание SPI 33 |
| IOMMU | собственный `kgsl-smmu-v2` по `0x01C40000` — у GPU свои виртуальные адреса |
| Питание | GDSC графики, шина `vdd`, уровень CX; голоса за шину BIMC |
| Такты | `core`, `iface`, `mem_iface`, `alt_mem_iface`, `rbbmtimer`, `alwayson` |
| Микрокод | `a530_pm4.fw`, `a530_pfp.fw` — открыто в linux-firmware |
| zap-шейдер | `a506_zap` — подписан под устройство, грузится через TrustZone (PIL) |

## Что такое freedreno и почему его нельзя «просто взять»

freedreno — это драйвер OpenGL ES в Mesa, в пространстве пользователя
Linux. Он не трогает железо сам: он собирает потоки команд и отдаёт их
ядерному драйверу `msm` через ioctl (`GEM_NEW`, `GEM_INFO`, `SUBMIT`,
`WAIT_FENCE`). Значит, для freedreno нужны две вещи, которых у нас нет:

1. **Ядерная часть** — то, что делает `drivers/gpu/drm/msm/adreno/a5xx_*`:
   питание и такты, загрузка микрокода, zap-шейдер через TrustZone,
   кольцевой буфер команд, таблицы IOMMU, прерывания и ограждения
   (fences). Прерываний в системе пока нет вовсе.
2. **Среда для Mesa** — libc, потоки, отображение памяти, компилятор
   шейдеров ir3 на NIR. Сотни тысяч строк, рассчитанных на Linux.

Порт Mesa целиком — это фактически построить совместимую с Linux среду.
Это годы, а не заходы.

## Путь «freedreno-lite»

Вместо порта — взять у freedreno знания и маленькие части:

- **G1. GPU просыпается.** Голоса за питание и такты, включение GDSC,
  чтение регистров RBBM без зависания шины. Проверка: осмысленные
  значения в регистрах, система жива.
- **G2. Процессор команд GPU работает.** Микрокод PM4/PFP из
  linux-firmware, zap-шейдер через TrustZone (вызовы SCM у нас уже есть,
  см. `arch/arm64/scm.c`), кольцевой буфер и команда `CP_NOP`. Проверка:
  указатель чтения кольца догнал указатель записи — GPU исполнил нашу
  команду.
- **G3. Память GPU.** Таблицы IOMMU для адресов GPU, буферы кадра и
  текстур. Проверка: GPU заливает буфер цветом, мы читаем результат.
- **G4. Композиция.** Шейдеры (сплошная заливка, текстурированный
  прямоугольник со смешиванием) компилируются **на компьютере** штатным
  ir3 из Mesa, в систему кладутся готовые двоичные программы. Отправитель
  потока команд — по образцу `fd5_emit.c`. Проверка: слой интерфейса
  выводится GPU.

G1–G2 — несколько заходов. G3–G4 — недели. Полный OpenGL ES для
приложений — отдельная большая история после G4.

**Нужно решение:** zap-шейдер `a506_zap` лежит только в разделе vendor
телефона (DerpFest). Без него A506 в защищённом режиме не стартует. Для
G2 его придётся скопировать с телефона через adb — только на компьютер,
не в репозиторий.

## Что уже сделано без GPU

Скорость, которую GPU дал бы интерфейсу, в заметной части достигается и
на процессоре — у A53 просто не было шансов:

| | было | стало |
|---|---|---|
| частота ядер | 800 МГц (загрузчик) | 2016 МГц |
| цвет | 8 бит, дизеринг | 24 бита, сглаживание |
| рисование рабочего стола | 213 мс | 37,7 мс |
| вывод полного кадра | 51 мс | 2,7 мс |
| ядер в работе | 1 | 4 (вывод кадра и крупные заливки полосами) |

Замер на телефоне: `posdev bench`.
