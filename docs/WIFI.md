# Wi-Fi на mido: что это на самом деле

Коротко: **в одну сессию не делается, и дело не в объёме кода.**
Разбор ниже — чтобы это был вывод, а не отговорка, и чтобы следующий
заход начинался не с нуля.

## Что за железо

Из дерева устройств самого телефона:

```
qcom,pronto@a21b000 {
    compatible = "qcom,pil-tz-generic";
    qcom,firmware-name = "wcnss";
};

qcom,wcnss_wlan { compatible = "qcom,wcnss_wlan"; ... }
```

Радио — не микросхема на шине, которой можно послать команду. Это
**отдельный процессор внутри кристалла** (WCNSS, он же Pronto) со своей
прошивкой. Наш процессор с ним разговаривает, а не управляет им.

## Почему это не "написать драйвер"

Цепочка, без единого звена которой нет ничего:

1. **Питание.** Семь источников: vddmx, vddcx, vddpx у самого Pronto и
   vddxo, vddrfa, vddpa, vdddig у радиочасти (iris). Все — за
   сопроцессором питания. Это единственное звено, которое у нас уже
   есть: канал открыт, просить умеем (см. `arch/arm64/smd_rpm.c`).

2. **Загрузка прошивки — через TrustZone.** `compatible` говорит
   `qcom,pil-tz-generic`: образ `wcnss.mdt` подписан, и загрузить его
   может только доверенная среда. Наш процессор не имеет права положить
   прошивку в память и отпустить чужой процессор из сброса — он обязан
   попросить TrustZone это сделать, вызовом SMC с описанием образа.
   Обойти нельзя: проверка подписи аппаратная.

3. **Сама прошивка.** Файлы лежат в разделе vendor (`/vendor/firmware/`).
   Их надо прочитать — то есть **нужна файловая система на eMMC**,
   которой у нас нет: ни драйвера SDHCI, ни ext4.

4. **Канал связи.** После старта Pronto с ним разговаривают по SMD —
   тому же самому, через который мы уже общаемся с сопроцессором
   питания (край 6 вместо 15). Это звено ближе всего к готовому.

5. **Протокол WCNSS_CTRL и драйвер WLAN.** Согласование версий,
   загрузка калибровочных данных, потом собственно 802.11: сканирование,
   подключение, шифрование WPA2.

6. **Сетевой стек.** ARP, IP, ICMP, UDP, DHCP — иначе подключение есть,
   а пользы нет.

## Что делать раньше вай-фая

Порядок не случаен: каждый следующий пункт опирается на предыдущий, и
каждый полезен сам по себе.

1. **Хранилище (SDHCI + чтение ext4).** Без него нет прошивок, нет
   своих файлов, нет ничего постоянного. И это же снимает зависимость
   от `fastboot boot` при каждом запуске.
2. **Вызовы TrustZone (SMC).** Нужны не только радио: через них идут и
   другие подсистемы.
3. **Загрузка подсистемы Pronto** и канал к ней.
4. **Сетевой стек.** Его можно писать и отлаживать РАНЬШЕ радио — на
   проводе: USB уже работает, и сделать из него сетевой интерфейс
   (CDC-ECM) заметно проще, чем поднять радио. Тогда `ping` будет
   настоящим, по IP, ещё до всякого вай-фая.

## Что есть уже сейчас

`posdev ping` — замер отклика по проводу. Это не ICMP, но проверяет он
ровно то, ради чего нужен: жива ли система и цела ли связь с ней от
начала до конца.
