# Wi-Fi на mido: что это на самом деле

Коротко: **в одну сессию не делается, и дело не в объёме кода.**
Разбор ниже — чтобы это был вывод, а не отговорка, и чтобы следующий
заход начинался не с нуля.

## Что за железо

Из дерева устройств самого телефона:

```
qcom,pronto@a21b000 {
    compatible = "qcom,pil-tz-generic";
    qcom,firmware-name = "wcnss";
};

qcom,wcnss_wlan { compatible = "qcom,wcnss_wlan"; ... }
```

Радио — не микросхема на шине, которой можно послать команду. Это
**отдельный процессор внутри кристалла** (WCNSS, он же Pronto) со своей
прошивкой. Наш процессор с ним разговаривает, а не управляет им.

## Почему это не "написать драйвер"

Цепочка, без единого звена которой нет ничего:

1. **Питание.** Семь источников: vddmx, vddcx, vddpx у самого Pronto и
   vddxo, vddrfa, vddpa, vdddig у радиочасти (iris). Все — за
   сопроцессором питания. Это единственное звено, которое у нас уже
   есть: канал открыт, просить умеем (см. `arch/arm64/smd_rpm.c`).

2. **Загрузка прошивки — через TrustZone.** `compatible` говорит
   `qcom,pil-tz-generic`: образ `wcnss.mdt` подписан, и загрузить его
   может только доверенная среда. Наш процессор не имеет права положить
   прошивку в память и отпустить чужой процессор из сброса — он обязан
   попросить TrustZone это сделать, вызовом SMC с описанием образа.
   Обойти нельзя: проверка подписи аппаратная.

3. **Сама прошивка.** Файлы лежат в разделе vendor (`/vendor/firmware/`).
   Их надо прочитать — то есть **нужна файловая система на eMMC**,
   которой у нас нет: ни драйвера SDHCI, ни ext4.

4. **Канал связи.** После старта Pronto с ним разговаривают по SMD —
   тому же самому, через который мы уже общаемся с сопроцессором
   питания (край 6 вместо 15). Это звено ближе всего к готовому.

5. **Протокол WCNSS_CTRL и драйвер WLAN.** Согласование версий,
   загрузка калибровочных данных, потом собственно 802.11: сканирование,
   подключение, шифрование WPA2.

6. **Сетевой стек.** ARP, IP, ICMP, UDP, DHCP — иначе подключение есть,
   а пользы нет.

## Что делать раньше вай-фая

Порядок не случаен: каждый следующий пункт опирается на предыдущий, и
каждый полезен сам по себе.

1. **Хранилище (SDHCI + чтение ext4).** Без него нет прошивок, нет
   своих файлов, нет ничего постоянного. И это же снимает зависимость
   от `fastboot boot` при каждом запуске.
2. **Вызовы TrustZone (SMC).** Нужны не только радио: через них идут и
   другие подсистемы.
3. **Загрузка подсистемы Pronto** и канал к ней.
4. **Сетевой стек.** Его можно писать и отлаживать РАНЬШЕ радио — на
   проводе: USB уже работает, и сделать из него сетевой интерфейс
   (CDC-ECM) заметно проще, чем поднять радио. Тогда `ping` будет
   настоящим, по IP, ещё до всякого вай-фая.

## Сделано: первый разговор с TrustZone

`arch/arm64/scm.c` — вызовы SMC по соглашению ARMv8 (как `scm_call2` в
ядре msm-4.9). По команде `q` по проводу система спрашивает TrustZone и
печатает ответы. На живом телефоне:

```
TZ: est li proverka zapuska podsistem -> kod 00000000 otvet 00000001
TZ: zapusk processora Wi-Fi (pas-id 6) podderzhan -> kod 00000000 otvet 00000001
```

То есть звено 2 из списка выше больше не гипотеза: доверенная среда
отвечает нам и подтверждает, что умеет запускать Pronto. Ничего не
меняется — только вопрос.

## Сделано: процессор Wi-Fi запущен, радио готово

Весь путь от голого кристалла до откалиброванного радио:

| Шаг | Где | Что |
| --- | --- | --- |
| Прошивка | `tools/fwpack.py`, `firmware.c` | `wcnss.mdt/bNN` и NV-файл из `~/mido/firmware` вшиваются в образ (в репозиторий — нет) |
| Питание | `pil.c` | CX/MX уровнями, L5/L7/L19/L9 через RPM |
| Iris | `pil.c` | выводы 76–80, буфер кварца `rf_clk2`, PMU Pronto: сброс, ID чипа, режим кварца |
| Запуск | `pil.c`, `scm.c` | `PAS_INIT_IMAGE` → `PAS_MEM_SETUP` → сегменты → `PAS_AUTH_AND_RESET` |
| SMEM-разделы | `smem_msm.c` | таблица `$TOC`: у пары «приложения — Wi-Fi» свой раздел |
| SMP2P | `pil.c` | своя половина (431), от Pronto `slave-kernel = 6` — «готов» |
| Канал SMD | `smd.c` | общий канал в разделе: открытие, посылки, опрос из фона |
| WCNSS_CTRL | `wcnss_ctrl.c` | версия → NV-файл кусками → холодная калибровка |

На живом телефоне (`POSl 1` по проводу):

```
PIL: Iris najden, kvarc 48 MGc
PIL: TrustZone proverila i zapustila processor
SMD: WCNSS_CTRL otkryt
WCNSS: versiya prosivki 1.5 1.2
WCNSS: NV prinyat, otvet 2
WCNSS: holodnaya kalibrovka zavershena, radio gotovo
```

Самым коварным оказались разделы SMEM. Pronto стартовал, открывал свой
канал к RPM, голосовал за питание — и «не заводил» каналов к нам. Заводил:
в разделе пары, куда мы просто не смотрели.

## Сделано: HAL, DXE, сканирование и экран Wi-Fi

| Шаг | Где | Что |
| --- | --- | --- |
| WLAN_CTRL | `wlan.c` | NV HAL-у, `START` с 45 параметрами, обмен возможностями, своя станция |
| DXE | `wlan_dxe.c` | четыре кольца в области обмена, опрос приёма без прерываний |
| Сканирование | `wlan.c` | `INIT_SCAN` → каналы 1–13 по 120 мс → `FINISH_SCAN`; разбор маяков |
| Интерфейс | `gui/touch/app_wifi.c`, `hal/hal_wifi.h` | переключатель, состояние, список сетей по уровню |

Прошивка сообщает о себе: `WCN v2.0 RadioPhy vIris_TSMC_4.0 with 48MHz XO`,
CRM `CNSS-PR-4-0-00328`, API 1.5.1.2. Включение с экрана до готового списка
сетей — около восьми секунд.

## Следующие шаги

1. **Передача через DXE** — дескриптор передачи (`wcn36xx_tx_bd`) и кадр.
2. **Подключение** — `CONFIG_BSS`/`CONFIG_STA`, `JOIN`, аутентификация и
   ассоциация.
3. **WPA2-PSK** — PBKDF2 из пароля, 4-way handshake по EAPOL, ключи в
   прошивку (`SET_BSSKEY`, `SET_STAKEY`); шифрует и расшифровывает она сама.
4. **Сетевой стек** — LLC/SNAP, ARP, IPv4, DHCP, ICMP (настоящий `ping`),
   затем UDP/TCP.

## Что есть уже сейчас

`posdev ping` — замер отклика по проводу. Это не ICMP, но проверяет он
ровно то, ради чего нужен: жива ли система и цела ли связь с ней от
начала до конца.
