# Запуск на реальном устройстве

Как собрать `boot.img` и как загрузить его на Redmi Note 4 и Pixel 6a.

## 0. Сначала неприятная правда

Образ **архитектурно подходит** обоим телефонам: это ARM64, ядро стартует с
корректным заголовком ARM64 Image, спускается из EL2 в EL1, поднимает MMU и
доходит до своей главной функции. Процессор действительно будет исполнять
наш код.

Но **вы ничего не увидите**, и вот ровно почему:

| Что нужно системе | Что она умеет сейчас | Есть ли это на телефоне |
|---|---|---|
| Консоль | PL011 **и** Qualcomm UARTDM, адрес из device tree | Да, для Snapdragon. Для Tensor нужен свой драйвер |
| Экран | `ramfb` под QEMU; готовый фреймбуфер загрузчика на железе | Скорее да, но формат и адрес нужно подтвердить на месте |
| Тачскрин | `virtio-input` | Нет. На телефоне контроллер сенсора сидит на шине I2C |

Адреса больше не зашиты в код: система разбирает device tree, который
передаёт загрузчик (см. [PORT_MIDO.md](PORT_MIDO.md)). Для Redmi Note 4 это
проверено на дереве из его же стокового образа. Но **тачскрина нет**, а
значит, интерфейсом будет не поуправлять — система это учитывает и без
устройств ввода сразу открывает экран «О системе» с диагностикой.

**Это не тупик, а понятный список работ** — см. раздел 5. Смысл прошивки на
текущем этапе один: убедиться, что загрузчик принимает образ и передаёт
управление. Проверять это лучше через `fastboot boot`, который ничего не
записывает в память устройства.

## 1. Сборка образа

```bash
make ARCH=arm64 image     # сырой ARM64 Image -> build/arm64/proshivkaos.img
```

Дальше сырой Image нужно упаковать в `boot.img`. Есть два пути.

### Путь А (надёжный): подменить ядро в стоковом образе

Так делают все, кто портирует ядро на реальный аппарат, и так следует делать
вам. Стоковый `boot.img` уже содержит правильные для этого конкретного
телефона базовый адрес, размер страницы, версию заголовка, командную строку,
device tree и ramdisk — угадывать ничего не надо, достаточно заменить один
кусок.

```bash
# magiskboot умеет распаковывать и собирать образы всех версий заголовка
magiskboot unpack stock_boot.img      # получится файл kernel и остальное
cp build/arm64/proshivkaos.img kernel
magiskboot repack stock_boot.img proshivkaos_boot.img
```

Вместо `magiskboot` подойдёт Android Image Kitchen (AIK) — тот же принцип.

### Путь Б: собрать с нуля нашим упаковщиком

Годится, когда стокового образа под рукой нет и параметры устройства
известны точно.

```bash
# Redmi Note 4 (Snapdragon), заголовок версии 0
make ARCH=arm64 bootimg BOOTIMG_BASE=0x80000000 BOOTIMG_PAGESIZE=2048

# Pixel 6a, заголовок версии 4
python3 tools/mkbootimg.py \
    --kernel build/arm64/proshivkaos.img \
    --header-version 4 \
    --os-version 13.0.0 --os-patch-level 2023-05 \
    --output build/arm64/proshivkaos_boot.img
```

## 2. Redmi Note 4

У модели две совершенно разные аппаратные версии, и это первое, что надо
выяснить — от неё зависят и параметры образа, и вообще всё:

| Версия | Кодовое имя | Процессор | Параметры boot.img |
|---|---|---|---|
| Global / India | `mido` | Snapdragon 625 (MSM8953) | база `0x80000000`, страница 2048, заголовок v0 |
| China | `nikel` | MediaTek Helio X20 (MT6797) | база другая; MTK-устройства часто требуют дополнительный заголовок на ядре |

Проверить: `adb shell getprop ro.product.device`.

Для `mido` значения по умолчанию в нашем Makefile совпадают с заводскими —
специально так подобраны. Для `nikel` идите путём А, не угадывайте.

```bash
# 1. Разлочить загрузчик (Xiaomi требует привязку Mi-аккаунта и ожидание,
#    обычно от нескольких дней до недели). ВНИМАНИЕ: стирает все данные.
fastboot oem unlock

# 2. Сохранить стоковый boot.img — это ваш путь назад
adb shell su -c "dd if=/dev/block/bootdevice/by-name/boot of=/sdcard/stock_boot.img"
adb pull /sdcard/stock_boot.img

# 3. Загрузиться БЕЗ записи в память устройства
fastboot boot proshivkaos_boot.img
```

`fastboot boot` на Snapdragon-устройствах Xiaomi работает и ничего не
портит: после перезагрузки телефон вернётся к штатной системе сам.

Важная особенность загрузчика LK на Qualcomm: он ожидает найти в образе
device tree в формате QCDT. Если собирать образ с нуля (путь Б) без него,
LK может отказаться загружаться. Ещё один аргумент за путь А.

**Отладочный UART.** На многих аппаратах Xiaomi на Snapdragon отладочный
последовательный порт выведен на разъём наушников и включается специальным
кабелем с делителем напряжения. Уточните схему именно для своей ревизии —
без неё вы не увидите даже отладочный вывод ядра.

## 3. Pixel 6a

Кодовое имя `bluejay`, процессор Google Tensor (GS101, родня Exynos).
Устройство современное, и это добавляет три отличия:

1. **Заголовок boot.img версии 4**, размер страницы 4096. Версия 0 не
   подойдёт — загрузчик её просто не примет.
2. **Разделы A/B.** Есть `boot_a` и `boot_b`, активный слот выбирается
   загрузчиком.
3. **GKI-разделение.** Ядро лежит в `boot.img`, а device tree и вендорский
   ramdisk — в отдельном `vendor_boot.img`. Наше ядро в них не нуждается,
   но трогать `vendor_boot` и не надо.

```bash
# 1. Разрешить разлочку: Настройки -> О телефоне -> 7 раз по номеру сборки,
#    затем в меню разработчика включить "OEM unlocking".
# 2. Разлочить. ВНИМАНИЕ: стирает все данные.
fastboot flashing unlock

# 3. Прошить в текущий слот
fastboot flash boot proshivkaos_boot.img
```

**Про `fastboot boot`.** На Pixel 6-й серии эта команда работает не на всех
версиях загрузчика — там, где не работает, она молча ничего не делает или
выдаёт ошибку. Если так, остаётся прошивка в слот, и тогда заранее
подготовьте способ вернуться.

**Как вернуться.** Google публикует заводские образы для всех Pixel — это
самая надёжная страховка из существующих. Скачайте образ для `bluejay`
заранее, до всех экспериментов; восстановление — `flash-all.sh` из архива.
Можно и точечно: `fastboot flash boot boot.img` из заводского архива.

**Отладочный UART.** У Pixel последовательная консоль выводится через
разъём USB-C специальным отладочным кабелем (SuzyQ / SuzyQable). Обычный
кабель для этого не годится.

## 4. Что вы реально увидите

Для Redmi Note 4 разбор ситуации подробно расписан в
[PORT_MIDO.md](PORT_MIDO.md) — там три сценария и что делать в каждом.
Коротко: если загрузчик оставил рабочий фреймбуфер, появится экран «О
системе» с диагностикой; если нет — чёрный экран, и дальше нужен
последовательный порт.

Для Pixel 6a результат почти наверняка будет чёрным экраном: драйвера
Samsung-совместимого порта Tensor в системе нет, а значит, нет и
отладочного вывода.

Косвенно отличить «загрузился и работает вслепую» от «не загрузился вообще»
можно так: при отказе загрузчика телефон либо перезагрузится в fastboot,
либо уйдёт в bootloop с перезагрузками каждые несколько секунд. Молчаливый
чёрный экран без перезагрузок — признак того, что код исполняется.

## 5. Порядок работ до «первого света»

Порядок именно такой: каждый следующий шаг проще отлаживать, когда работает
предыдущий.

1. ~~**Разбор device tree.**~~ **Сделано.** Адреса порта, контроллера
   прерываний и готового фреймбуфера берутся из дерева, которое передаёт
   загрузчик — см. [`arch/arm64/fdt.c`](../arch/arm64/fdt.c). Разбор
   проверен на дереве от QEMU и на вытащенном из стокового образа Redmi
   Note 4.
2. **UART устройства.** Для Qualcomm **сделано**:
   [`arch/arm64/uart_msm.c`](../arch/arm64/uart_msm.c), блок UARTDM версии
   1.4 — он стоит на всех Snapdragon этого поколения. Какой драйвер
   использовать, решается во время выполнения по `compatible` из дерева,
   так что один образ подходит и эмулятору, и телефону.
   Для Tensor (Pixel) драйвера пока нет: там Samsung-совместимый
   контроллер с другим набором регистров.
3. **Экран через готовый фреймбуфер.** Полноценный драйвер DSI писать не
   нужно: загрузчик уже настроил контроллер дисплея, чтобы показать свой
   логотип, и оставил работающий фреймбуфер. Его адрес и формат лежат в том
   же DTB под именем `framebuffer-simple`. Достаточно передать их в
   `gfxfb_bind()` — и весь интерфейс появится на экране как есть.
4. **Тачскрин.** Контроллеры Goodix/Focaltech/Synaptics сидят на I2C. Нужен
   драйвер I2C конкретного процессора плюс разбор протокола контроллера.
   Слой выше ([`hal/hal_input.h`](../hal/hal_input.h)) уже принимает
   абсолютные координаты — ему всё равно, откуда они пришли.

Шаги 1-3 дают загружающуюся систему с картинкой на экране. Шаг 4 делает её
управляемой пальцем.
