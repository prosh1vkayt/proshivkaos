# Тач-интерфейс proshivkaOS NEXT

Оболочка для устройств с сенсорным экраном — то, что в postmarketOS делает
Phosh: ядро и приложения остаются обычными, вся «телефонность» живёт в
отдельном слое оболочки.

Собирается профилем `touch` и работает на **обеих** архитектурах:

```bash
make ARCH=arm64 touch-run     # тачскрин через virtio-input, экран через ramfb
make touch-run                # то же самое на x86: мышь изображает палец
```

## 1. Почему нельзя было просто уменьшить окна

Десктопная оболочка (`gui/wm.c`) не масштабируется на телефон — и дело не
в размере экрана:

| | Десктоп (`gui/wm.c`) | Тач (`gui/touch/`) |
|---|---|---|
| Окна | перекрывающиеся, с рамкой и заголовком | одно приложение на весь экран |
| Указатель | курсор, есть состояние «навёл, но не нажал» | палец: либо касается, либо нет |
| Подсветка | по наведению | только по нажатию |
| Срабатывание | по нажатию кнопки | по **отпусканию** — можно отвести палец и передумать |
| Размер цели | сколько нарисовали, столько и есть | не меньше ~7 мм, иначе не попасть |
| Выход из приложения | кнопка «закрыть» в углу | жест или панель навигации |
| Ввод текста | клавиатура есть всегда | клавиатуры нет, её надо нарисовать |

Две форточки шириной 150 точек на экране 480x960 — это две нечитаемые
полоски. Поэтому оболочка написана заново, а вот **приложения переиспользованы
как есть**: `gui/terminal_app.c` (разбор команд, RamFS, `cd`/`ls`/`cat`/`edit`)
работает в обеих сборках без единой правки — ему поменяли только область
вывода и масштаб шрифта.

## 2. Из чего состоит

```
gui/touch/
├── touch_ui.c      оболочка: домашний экран, статусбар, навбар,
│                   переключатель приложений, распознавание жестов
├── touch_theme.c   метрики и готовые элементы (карточка, кнопка,
│                   иконка, переключатель)
├── osk.c           экранная клавиатура, две раскладки
├── touch_app.h     контракт приложения
├── app_terminal.c  терминал      (обёртка над gui/terminal_app.c)
├── app_files.c     файловый менеджер поверх RamFS
├── app_settings.c  настройки тач-элементами вместо текстового меню
└── app_about.c     «о системе»
```

Приложение — это структура с указателями на функции (`touch_app_t`).
Добавить своё = написать один `.c` и вписать его в список `g_apps[]` в
`touch_ui.c`. В десктопной оболочке приложения были вшиты в цикл обработки
мыши, и добавление третьего означало правку десятка мест.

## 3. Размеры считаются, а не задаются

В десктопной теме размеры — константы (`TITLE_BAR_H 10`, `TASKBAR_H 14`):
разрешений было три и все известны заранее. Здесь так нельзя — экран
телефона бывает любым, а палец у пользователя во всех случаях одинаковый.

Базовая единица — **минимальная тач-цель**, а не пиксель:

```c
TM.touch  = screen_w / 11;   /* ~7 мм при типичной плотности */
TM.pad    = TM.touch / 5;
TM.scale  = screen_w / 240;  /* масштаб шрифта 8x8 -> 16x16 или 24x24 */
```

Всё остальное — производные. Поэтому одна и та же сборка корректно
раскладывается и на 480x960, и на 720x1440:

```bash
make ARCH=arm64 touch SCREEN_W=720 SCREEN_H=1440
```

Число колонок в сетке приложений подстраивается под форму экрана: три в
портрете, пять в ландшафте.

## 4. Ввод

Единая модель указателя (`hal/hal_input.h`) — `POINTER_DOWN` / `MOVE` / `UP`
с абсолютными координатами. Приводят к ней два очень разных источника:

- **x86** (`hal/hal_input_x86.c`): PS/2-мышь шлёт относительные смещения,
  бэкенд сам ведёт положение курсора и разбирает фронты нажатия;
- **ARM64** (`hal/hal_input_arm64.c`): virtio-input шлёт абсолютную точку
  в своей сетке (0..32767), бэкенд масштабирует её в пиксели.

Оболочка разницы не видит. `hal_input_has_cursor()` отвечает, надо ли
рисовать стрелку: на тачскрине — не надо.

Устройство ввода шлёт координату X, координату Y и состояние касания
**разными** событиями, а «кадром» их делает `EV_SYN`. Без этой группировки
палец на диагональном свайпе двигался бы ступеньками.

Третий источник — **последовательный порт**: всё, что приходит в
serial-консоль, попадает в систему как нажатия клавиш. Это не костыль, а
рабочий режим ранних этапов порта: экранной клавиатуры может ещё не быть,
тачскрин может не завестись, а UART работает всегда.

## 5. Жесты и навигация

- **Панель навигации** снизу: «назад», «домой», «список запущенных».
  Значки нарисованы примитивами, а не буквами — стрелка и круг узнаются
  мгновенно.
- **Свайп снизу вверх** из зоны навбара — домой. Порог: полторы тач-цели,
  иначе дрожание пальца на кнопке считалось бы жестом.
- Экранная клавиатура появляется сама, если у приложения есть куда
  печатать (`wants_keyboard()`), и убирается своей клавишей. Область
  приложения при этом пересчитывается — клавиатура ничего не перекрывает.

## 6. Отрисовка

Перерисовка **событийная**: кадр строится, только если что-то произошло,
плюс раз в секунду ради часов. Покадровой анимации нет — на программном
рендере без GPU она стоила бы дороже, чем даёт.

Всё рисование идёт индексами палитры (`gui/palette.h`), даже там, где у
железа честный 32-битный цвет. Благодаря этому интерфейс, написанный под
VGA mode13h, работает на телефоне без правок, а преобразование индексов в
RGB делается один раз за кадр в `gfxfb_present()`.

Индексы 32..47 отведены под тёмную тач-тему. Тёмная она не ради моды: на
OLED чёрный пиксель — это выключенный пиксель, то есть буквально нулевое
потребление.

Запечённые обои (`gui/wallpaper_*.c`) в тач-сборку **не входят**: они
нарисованы под ландшафтные 4:3 и на портретном экране бесполезны. Фон —
дизеринг-градиент, он растягивается на любое разрешение.

## 7. Что дальше

- **Инерционная прокрутка** — нужна покадровая анимация, то есть отрисовка
  по таймеру вместо событийной.
- **Мультитач** (щипок для масштаба) — `virtio-input` умеет слоты
  multitouch, модель события в `hal_input.h` придётся расширить.
- **Поворот экрана** — метрики уже пересчитываются от разрешения, нужен
  датчик и поворот буфера при выводе.
- **Индикатор заряда** — на реальном устройстве читается из PMIC по I2C,
  место под него в статусбаре уже предусмотрено.
- **Строчные буквы в шрифте** — сейчас всё приводится к заглавным, это
  черта оформления системы, но для терминала лишняя.
