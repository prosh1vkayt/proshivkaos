# proshivkaOS NEXT — архитектура

Система собирается под **две архитектуры** (x86, ARM64) в **три профиля**
(текстовый shell, оконный интерфейс, тач-интерфейс). Подробности по ARM64 —
в [ARM64_PLAN.md](ARM64_PLAN.md), по тач-оболочке — в [TOUCH_UI.md](TOUCH_UI.md).

```
                    ARCH=x86              ARCH=arm64
   text     текстовый shell в VGA   текстовый shell в UART
   gui      оконный интерфейс (XP)          —
   touch    тач-интерфейс (мышь      тач-интерфейс (тачскрин
            изображает палец)         через virtio-input)
```

## 1. Дерево каталогов

```
proshivkaos-next/
├── Makefile                     # ARCH=x86|arm64, профили text/gui/touch
├── linker.ld                    # линковка ядра для x86 (Multiboot, 1 MiB)
├── boot/boot.asm                # NASM/Multiboot, точка входа x86
│
├── kernel/
│   ├── kernel.c                 # kmain() текстового профиля
│   ├── kernel_gui.c             # kmain() оконного профиля
│   ├── kernel_touch.c           # kmain() тач-профиля — ОДИН на обе архитектуры
│   ├── kstring.c                # memset/memcpy/memmove/memcmp
│   ├── panic.c / panic_gui.c    # kpanic() в консоль / во фреймбуфер
│
├── hal/                         # единый API, за которым спрятана платформа
│   ├── hal.h                    # консоль, память, потоки, hal_arch_init()
│   ├── hal_time.h               # монотонное время в мс + календарь
│   ├── hal_input.h              # единая модель указателя: DOWN/MOVE/UP
│   ├── hal_console.c            # x86-бэкенд консоли (VGA + PS/2)
│   ├── hal_console_arm64.c      # ARM64-бэкенд консоли (PL011 + ANSI-цвет)
│   ├── hal_input_x86.c          # мышь: относительные смещения -> точка
│   ├── hal_input_arm64.c        # virtio-input: сетка сенсора -> пиксели
│   ├── hal_time_x86.c           # TSC, откалиброванный по PIT
│   ├── hal_mem.c                # bump-аллокатор (арх-нейтральный)
│   └── hal_thread.c             # заготовка API потоков
│
├── arch/
│   ├── x86/
│   │   ├── vga.c, keyboard.c, mouse.c, cpu.c, rtc.c, pit.c
│   │   ├── vga13h.c, vbe.c, pci.c        # графические режимы
│   │   └── hal_gfx_x86.c                 # инициализация экрана: mode13h/VBE
│   └── arm64/
│       ├── boot.S               # заголовок ARM64 Image, EL2->EL1, .bss, стек
│       ├── vectors.S            # таблица векторов исключений (аналог IDT)
│       ├── linker.ld            # размещение по RAM_BASE + text_offset

│       ├── uart.c               # PL011 — аналог vga.c

│       ├── virtio_input.c       # тачскрин/клавиатура — аналог mouse.c+keyboard.c
│       ├── cpu.c                # wfi, обработчик исключений
│       └── hal_gfx_arm64.c      # инициализация экрана: ramfb

│   ├── hal_gfx.c/.h             # примитивы: заливки, градиенты, текст
│   ├── gfxfb.c/.h               # двойная буферизация, форматы PAL8/XRGB32
│   ├── palette.c/.h             # единая таблица цветов
│   ├── font8x8.c                # шрифт: A-Z, 0-9, вся печатная пунктуация
│   ├── gconsole.c               # текстовая консоль: окно ИЛИ прямоугольник
│   ├── terminal_app.c           # разбор команд — общий для gui и touch
│   ├── window.c, wm.c           # оконный менеджер (только профиль gui)
│   ├── wallpaper*.c, cursor.c   # обои и курсор десктопа
│   └── touch/                   # тач-оболочка (профиль touch, обе архитектуры)

├── shell/shell.c                # командная строка текстового профиля

├── tools/mkbootimg.py           # упаковка в Android boot.img
└── docs/
```

**Идея разделения:** `kernel/`, `shell/`, `fs/` и вся `gui/` (кроме `wm.c`)
пишутся **один раз** и не знают, на какой архитектуре исполняются — они
дёргают только функции из `hal/`. Вся специфика (VGA vs UART, GRUB vs LK,
IDT vs GIC, PS/2 vs virtio-input) прячется в `arch/<платформа>/`.

Ключевой инвариант: **ни один файл вне `arch/` не содержит `#ifdef` по
архитектуре**. Выбор бэкенда делает Makefile, подставляя в сборку нужный
`.c` — например, `hal_console.c` **или** `hal_console_arm64.c`.

## 2. Слои

```
                +-------------------------------------+
                |    apps/ (userland) + gui/touch/     |
                +------------------+-------------------+
                                   |  app_api.h, touch_app.h
                +------------------v-------------------+
                |   gui/ (примитивы, консоль, шрифт)    |
                |   shell/ + fs/ (RamFS)                |   арх-независимые
                +------------------+-------------------+
                                   |
                +------------------v-------------------+
                |               hal/                    |   единственный API
                |  console | mem | time | input | gfx    |
                +--------+---------------------+--------+
                         |                     |
            +------------v------+   +----------v-----------+
            |     arch/x86/      |   |     arch/arm64/       |
            | vga, ps/2, vbe,    |   | pl011, ramfb,         |
            | rtc, pit           |   | virtio-input, mmu,    |
            |                    |   | generic timer         |
            +--------------------+   +-----------------------+
```

### 2.1 Память (`hal_mem`)

Bump-аллокатор поверх статического региона в `.bss`. Архитектурно
нейтрален — отличается только то, откуда взялся регион. Освобождение пока
не реализовано (задел под free-list).

### 2.2 Время (`hal_time`)

```c
uint64_t hal_time_ms(void);   /* монотонное, с момента старта */
void hal_time_rtc(int *y, int *mo, int *d, int *h, int *mi, int *s);
```

Миллисекунды, а не секунды: тач-интерфейс без них не сделать — тап от
свайпа отличается не столько длиной жеста, сколько его длительностью.

- **x86**: TSC, один раз откалиброванный по таймеру PIT (его частота
  задана кварцем ещё в IBM PC и одинакова везде); календарь — CMOS RTC.
- **ARM64**: ARM Generic Timer (`CNTPCT_EL0`) — читается обычной `mrs`,
  без MMIO и прерываний, есть на любом ARM; календарь — PL031.

### 2.3 Ввод (`hal_input`)

Единая модель указателя `DOWN / MOVE / UP` с абсолютными координатами
плюс события клавиш. К ней приводятся два принципиально разных источника:
относительная PS/2-мышь и абсолютный тачскрин. Оболочка разницы не видит.
См. [TOUCH_UI.md](TOUCH_UI.md), раздел 4.

### 2.4 Графика (`hal_gfx` + `gfxfb`)

Рисование везде идёт **индексами палитры**, даже там, где у железа честный
32-битный цвет. Благодаря этому интерфейс, написанный под VGA mode13h,
работает на телефоне без правок. Преобразование индекс → RGB делается один
раз за кадр, при выводе кадра на экран:

- `GFXFB_FMT_PAL8` — байт на пиксель, цвет подставляет DAC видеокарты (x86);
- `GFXFB_FMT_XRGB32` — четыре байта, честный RGB (ARM64, реальные дисплеи).

### 2.5 Потоки (`hal_thread`) — по-прежнему заготовка

API есть, вытесняющего планировщика нет: `hal_thread_create()` вызывает
функцию синхронно. Реализация (переключение контекста в ASM отдельно для
x86 и ARM64 плюс GIC/IDT) — следующий этап, общий для обеих архитектур.

## 3. Чего пока нет

- прерываний (ни IDT/PIC на x86, ни GIC на ARM64) — всё опрашивается в цикле;
- вытесняющего планировщика и изоляции процессов;
- освобождения памяти;
- постоянного хранилища — RamFS живёт только до перезагрузки;
- разбора device tree на ARM64 (адреса пока зашиты под QEMU virt).
